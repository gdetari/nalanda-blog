# Dharma

A small, text-first blog with warm paper tones, Georgia typography, a narrow
reading column, and no scripts, tracking, ads, or external fonts. It has an
Ink-inspired design but is not the upstream Astro Ink theme. The site starts
empty; no example text is published as your work.

## Write using Obsidian

Keep your normal vault and drafts outside this repository. In Obsidian, open
the `posts/` folder as a separate vault for finished, public posts. The
`.obsidian/` settings generated by the app are ignored by Git.

1. Make a new note in that vault, e.g. `first-essay.md`. Lowercase and hyphens
   make your web address easy to share.
2. Use the properties shown in the root `POST-TEMPLATE.md`. Only `title` and
   `date` are required; use YYYY-MM-DD.
3. Use standard Markdown. For links, use `[label](https://example.com)` or
   `[another post](../another-post/)`, not Obsidian-specific wiki links or
   embeds.
4. Commit and push your public post to the repository's `main` branch. GitHub
   builds the new site from the files in `posts/`. Saving locally does not
   publish by itself.

**Privacy:** A free GitHub Pages repository is public. Never copy unpublished
drafts, personal notes, or credentials into it, even if a note has a draft
property. Review what Git is about to commit. Use a separate repository for
this site rather than connecting your main Obsidian vault.

## Preview

Requires Python 3 and Pandoc (`brew install pandoc` on macOS, if using Homebrew).
From the repository root:

    python3 build.py
    python3 -m http.server --bind 127.0.0.1 --directory dist 8000

Open <http://localhost:8000>. The builder uses relative-to-site links; in CI the
site root or GitHub project path comes from Pages configuration.

## Free GitHub Pages deployment

1. Create a new **public** GitHub repository, add these files, and push them to
   `main`. Do not add `dist/` or private Obsidian files.
2. In **Settings → Pages**, choose **GitHub Actions** as the build and
   deployment source. Run **Publish blog** under **Actions** if the initial
   push ran before Pages was configured.
3. Open the URL shown by GitHub Pages and verify it loads before touching DNS.
4. For **dharma.detari.dev**, it is prudent to verify the domain in GitHub
   before assigning it. Add `dharma.detari.dev` in the repository's **Settings
   → Pages → Custom domain**. At the DNS provider, add a CNAME for host
   `dharma` targeting `YOUR-GITHUB-USERNAME.github.io` (your actual Pages
   account, not the repository path). Do not overwrite existing records
   without confirming what they serve. No changes to detari.dev's apex or
   email records are needed.
5. When DNS and the TLS certificate are ready, enable **Enforce HTTPS**.
   Rerun **Publish blog** so canonical URLs and assets reflect the final host.
